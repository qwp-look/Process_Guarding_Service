# 守护功能

守护功能是 PGS 的核心：把一个程序注册给 PGS，PGS 会观察它的退出状态，并按策略决定是否重启。

## 基础行为

- 正常取消守护或标记 intentional 后，PGS 不会再拉起目标。
- 异常退出时，PGS 按最大重启次数决定是否重启。
- 服务重启后，PGS 会读取归档并恢复仍应守护的对象。
- `bless-start` 会先启动程序再注册守护，适合普通 Win32 程序。

## 常用策略

- 最大重启次数：限制崩溃循环。
- 重启窗口：只统计一段时间内的重启次数。
- 重启延迟：异常退出后等一会儿再拉起。
- 指数退避：连续失败时逐步拉长等待时间。
- 假活检测：对有窗口的程序做简单 hang 探测。
- 退出连杀：PGS 退出时是否一并结束目标进程族。

普通用户可以先只设置最大重启次数。其它策略适合服务端程序、容易崩溃的程序或需要严格恢复节奏的场景。

## WindowsApps 当前用法

WindowsApps / Store / UWP 应用的启动方式和普通 exe 不一样。当前版本采用显式 AUMID 的“先启动，再注册”流程：

1. 先手动启动 Store 应用。
2. 找到对应 PID。
3. 使用 `--winapp --aumid <id>` 注册。

`bless-start --winapp` 当前会被拒绝；自动识别 AUMID 也尚未实现。这两项已记录在未完成功能交接文档中。
