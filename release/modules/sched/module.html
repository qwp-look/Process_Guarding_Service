计划任务模块 (pgs_sched_module) [ABI v2]

功能：按 cron / 一次性 / 间隔 三种方式定时执行受限的 PGS 命令（bless / unbless / policy 等）， 到期自动触发。这是 PGS 模块系统中首个 ABI v2 模块：通过 PGS_Services 回调从自己的 后台线程反向调用 PGS，不再是无状态请求/响应插件。

支持的操作 (op)

操作说明请求示例 (KV)
add新增一条计划op=add;type=cron;expr=*/2 * * * *;action=bless 1234|-1
list列出全部计划op=list
remove按 id 删除计划op=remove;id=7
enable启用某条计划op=enable;id=7
disable停用某条计划op=disable;id=7

调度类型与 expr 取值

typeexpr 取值可选说明
cron分 时 日 月 周（5 段）-标准 cron 语义，分钟粒度
onceYYYY-MM-DDTHH:MM:SS-一次性，触发后自动禁用
interval正整数秒count=N每 N 秒一次，可限定次数

cron 字段

分 0-59、时 0-23、日 1-31、月 1-12、周 0-6（0=周日）。 支持 *（任意）、a-b（范围）、a,b,c（列表）、star/n（步进）。

日(DOM)与周(DOW)：当两者都被限制时按 Vixie cron OR 语义（匹配任一即触发）； 其中之一为 *（任意）时只看被限制的那个；两者都 * 则每天触发。 不支持月份/周英文缩写（纯数字）。

便捷命令 (pgs_bless schedule)

无需手写 module-call 语法，可直接使用 schedule 子命令（内部自动路由到本模块）：

pgs_bless schedule add --cron "*/2 * * * *" --action "bless 1234|-1"
pgs_bless schedule add --once "2026-07-10T15:30:00" --action "unbless 1234"
pgs_bless schedule add --interval 300 --count 5 --action "policy 1234|no"
pgs_bless schedule list
pgs_bless schedule remove --id 1
pgs_bless schedule disable --id 2
pgs_bless schedule enable --id 2

或通过通用模块调用：

pgs_bless module call --name sched --request "op=add;type=cron;expr=0 2 * * *;action=ping"

动作白名单

调度可执行的命令限定为守护管理类动词，显式排除提权/破坏性操作：

允许bless register unbless unregister policy set-policy intentional list get ping
禁止token-set module load/unload service install/stop/uninstall ppl
防提权硬约束：即使 pgs_sched.db 被篡改，也无法通过调度执行高危命令。

错过执行策略（服务停机后恢复）

  • once：若到期时间已过且仍启用，PGS 重启后补跑一次然后禁用。
  • cron / interval：不补跑历史，按当前时钟重算下一个到期点（避免重启风暴）。

持久化

调度状态存于本目录下 pgs_sched.db（与 DLL 同目录），文本 KV，原子写（tmp + 替换）。 字段：id;type;expr;action;enabled;last_run_ms;next_run_ms;run_count;max_count。 PGS（被 SCM）重启后模块在 PG_Init 重新加载并按错过执行策略重算。

响应格式

成功返回 OK ...，失败返回 ERR ...。例如：

OK added id=1 next_run_ms=1783578600000
OK count=2
ID=1;TYPE=cron;EXPR=0 2 * * *;ACTION=bless 1234|-1;ENABLED=1;...
OK removed id=1
ERR action not in allowlist: token-set ...
ERR invalid cron expression
运行前提：
  • PGS 需开启普通模块加载（PGS_ENABLE_MODULES=1 或 --enable-modules）才会扫描加载 modules/。
  • 本模块已写入默认 modules.lock 信任文件，并保留 modules.allow 兼容项（sched）。
  • 本目录的 MinGW 运行时 DLL（libstdc++-6.dll 等）随模块分发，供独立运行。
