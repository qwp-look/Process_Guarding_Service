PPL 模块 (pgs_ppl_module)

功能：对目标进程设置 / 查询 / 清除 PPL（Protected Process Light）保护级别。 内部复用 Sirius.sys 内核驱动（源自 StarlightGUI，Apache-2.0，作者 Stars）， 通过统一的 IOCTL 协议与驱动通信。本模块现在是 PGS 模块生态里的高危普通模块： 只有通过 modules.lock/modules.allow 信任校验，并显式开启 kernel/risk 开关后，核心 loader 才会加载和调用它。

支持的操作 (op)

操作说明请求示例 (KV)
set为指定进程设置 PPL 保护级别op=set;pid=1234;signer=Antimalware
get查询指定进程当前的 PPL 保护级别op=get;pid=1234
clear清除指定进程的 PPL 保护（设为 None）op=clear;pid=1234

Signer 取值表

ProtectionType 固定为 PsProtectedTypeProtectedLight（与 StarlightGUI 的 SetPPL 行为一致）， 仅 signer 可变；clear 例外（type=None）。也支持传原始数字（0-255）。

Signer 名称含义
None无保护
AuthenticodeAuthenticode 签名
CodeGen代码生成
Antimalware反恶意软件（AM，常见保护级别）
Lsa本地安全机构
WindowsWindows 系统进程
WinTcbWindows 受信任计算基（最高保护）
WinSystemWindows 系统级
App应用级

便捷命令 (pgs_bless ppl)

无需记忆 module invoke 语法，可直接使用 ppl 子命令（内部自动路由到本模块的 JSON-RPC 方法）：

pgs_bless ppl set   --pid 1234 --signer Antimalware
pgs_bless ppl get   --pid 1234
pgs_bless ppl clear --pid 1234

或通过通用模块调用：

pgs_bless module invoke --name ppl --method ppl.set --params-json "{"pid":1234,"signer":"Antimalware"}"
pgs_bless module call --name ppl --request "op=set;pid=1234;signer=Antimalware"  # 兼容 KV

响应格式

成功返回 OK ...，失败返回 ERR ...。例如：

OK set signer=Antimalware type=ProtectedLight pid=1234
OK get signer=Antimalware type=ProtectedLight pid=1234
ERR driver not loaded
ERR invalid pid
运行前提：
  • 机器需能加载 Sirius.sys 内核驱动（测试签名模式，或其既有签名；StarlightGUI 能跑即满足）。
  • PGS 服务需以 SYSTEM 权限运行，否则无权操作进程 PPL。
  • PGS 服务需显式开启 --enable-kernel-modules / --enable-risk critical（或兼容 --enable-ppl）。普通 --enable-modules 不会单独放行 PPL。
  • 若驱动未加载，set 会返回驱动错误（不崩溃），get 仍可查询已存在的保护。
